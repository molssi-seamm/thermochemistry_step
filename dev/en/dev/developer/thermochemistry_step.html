thermochemistry_step.cbh_approach module#

The isodesmic (CBH) approach with ATcT references.

The enthalpy of formation of the target molecule is obtained from an error-cancelling reaction of the connectivity-based hierarchy (CBH), whose other species have reference enthalpies of formation in the Active Thermochemical Tables (ATcT):

ΔfH(target, T) = Σ_j ν_j ΔfH_j(ATcT, T) - Δ_rH(T)

with Δ_rH(T) = Σ_i ν_i H_i(T) computed with the subflowchart’s engine for every species (the target has ν = -1). The reaction, the ATcT lookups, the covariance-propagated 95 % uncertainty and the combination are done here; the science lives in seamm_thermochemistry (atct and cbh).

The energies H_i(T) come from one of three places:

  • “finite-difference harmonic”: the subflowchart is run on each species, first to optimize it (ASE BFGS) and then for the finite-difference Hessian; the rigid-rotor harmonic-oscillator thermochemistry of the Harmonic approach gives H(0 K) = E + ZPE and H(298.15 K);

  • “finite-difference harmonic” with “thermal corrections” = none: the subflowchart’s energy already is the enthalpy of formation at 298.15 K, as for MOPAC’s NDDO methods, so only Δ_rH(298.15 K) is formed;

  • “existing results (run nothing)”: the species’ energies are read from properties already stored on the systems named CBH:<SMILES> (and the target), e.g. by an earlier parallel Loop, so the expensive part can be run in parallel and at two levels of theory.

Results are reported at 0 K and 298.15 K and paired with the ATcT values at the same temperature, never converted between them. ATcT’s plain gas-phase entries are the lowest conformer at 0 K and a conformer average at 298.15 K, so the 0 K comparison is the cleaner one for a single-conformer calculation.

thermochemistry_step.hessian module#

The energy and Hessian of a structure from the flowchart’s Model Chemistry.

The Model Chemistry step upstream publishes _model_chemistry; the program behind it is driven through seamm_exec.Evaluator, either as a warm MDI engine (seamm_mdi.MDIEngine) or as separate calculations (tasks) where the job runs them. The route follows the Normal Mode Sampling step (design of 2026-10-03):

  • on a queue target the finite difference runs as tasks on the cluster, with no local engine started even to ask;

  • otherwise the analytic Hessian over MDI when the program offers one (the engine advertises the custom <HESSIAN command only when the method has a genuine analytic Hessian), else central finite differences of the forces over the warm engine, or as tasks when the evaluator chose that path;

  • with no MDI engine, the finite difference as tasks.

This mirrors normal_mode_sampling_step’s driver, with the energy of the undisplaced structure collected as well. It belongs in a shared library once a third consumer appears.

thermochemistry_step.symmetry module#

The rotational symmetry number of a molecule, perceived from its geometry.

The symmetry number σ is the number of proper rotations (including the identity) in the molecule’s point group: the number of indistinguishable orientations reached by rotation alone. It enters the rotational partition function as 1/σ, i.e. the entropy as -R ln σ. This module finds σ by testing candidate rotation axes directly against the structure, which needs no point-group assignment and no external library.

Candidate axes are the principal axes of inertia, the vectors from the centre of mass to each atom, the midpoints and cross products of pairs of like atoms, and the normals of planes through triples of like atoms. For every candidate axis and every order n from 2 up to the largest number of atoms of one element, the rotation by 2π/n is applied and accepted if it maps every atom onto an atom of the same element within the tolerance.

Bases: object

Helper class needed for the stevedore integration.

This must provide a description() method that returns a dict containing a description of this node, and create_node() and create_tk_node() methods for creating the graphical and non-graphical nodes.

The dictionary for the description is the class variable just below these comments. The felds are as follows:

my_description{str, str}

A human-readable description of this step. It can be several lines long, and needs to be clear to non-expert users. It contains the following keys: description, group, name.

my_description[“description”]tuple

A description of the Thermochemistry step. It must be clear to non-experts.

my_description[“group”]str

Which group in the menus to put this step. If the group does not exist it will be created. Common groups are “Building”, “Control”, “Custom”, “Data”, and “Simulations”.

my_description[“name”]str

The name of this step, to be displayed in the menus.
